# yt-audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust CLI `yt-audio` that downloads YouTube audio (videos and
playlists) and writes clean, multi-valued music tags, with an optional LLM
fallback for title parsing.

**Architecture:** Pure, unit-tested core (title patterns, metadata resolution,
path layout, command-line construction) wrapped by thin I/O shells (yt-dlp
subprocess, lofty tag writer, LLM client behind the `llm` Cargo feature). The
repo becomes a Cargo workspace so pre-commit and Nix cover both Rust crates.

**Tech Stack:** Rust 2024, clap 4 (derive + env), serde/serde_json, thiserror,
lofty 0.22, llm 1.3 (`default-features = false`,
`openai`,`ollama`,`rustls-tls`) + tokio (optional), Nix flakes, Forgejo/GitHub
Actions with Swatinem/rust-cache.

**Spec:** `docs/superpowers/specs/2026-10-18-yt-audio-design.md`

## Global Constraints

- Crate at `tools/yt-audio`, binary `yt-audio`, `edition = "2024"`,
  `rust-version = "1.85"` (raise only if a dependency's MSRV forces it),
  `[lints.rust] unsafe_code = "forbid"`, MIT.
- Same shape as `tools/ls-posts`: `main.rs` calls
  `yt_audio::run(args, &mut stdout, &mut stderr) -> i32`; exit codes `0` ok, `1`
  runtime failure or any entry failed, `2` usage error.
- Diagnostics to stderr prefixed `"yt-audio: "`; `--dry-run` report to stdout.
- Refuse to run when effective uid is 0: message
  `yt-audio: refusing to run as root`, exit 1.
- Runtime deps `yt-dlp`, `ffmpeg` resolved from `PATH` (Nix wrapper provides
  them).
- Every yt-dlp call passes `--ignore-config` so a user's yt-dlp config cannot
  change behaviour.
- LLM API key from env var `YT_AUDIO_LLM_KEY` only — never a flag, never logged.
- No network in any non-`#[ignore]` test.
- Commits: `feat(yt-audio): …` / `ci: …` / `build: …`, trailer
  `Co-authored-by: Claude Opus 5.5 <noreply@anthropic.com>` and nothing else
  agent-related (no session links). Never push.

## Review Focus

1. Titles containing a filesystem-hostile character (`/`, `:` is fine) or that
   sanitise to empty → file still written, name non-empty (Task 3:
   `sanitize_empty_becomes_underscore`, `sanitize_slash`).
2. A title matching no pattern and no YouTube music fields (e.g.
   `【MV】 ただの曲名`) → fallback gives title `ただの曲名`, artist = channel
   (Task 4: `fallback_uses_channel_minus_topic`).
3. YouTube music fields present but **partial** (artist but no track) →
   per-field merge, title from pattern/fallback (Task 4:
   `partial_youtube_fields_merge_per_field`).
4. One playlist entry failing (private/deleted video) → others still processed,
   exit 1, summary names the failure (Task 7:
   `run_continues_after_entry_failure`).
5. LLM returns names not present in the input, or garbage JSON → discarded,
   falls back without aborting (Task 8: `guard_drops_invented_artist`,
   `parse_rejects_garbage`).

### Task 2: Title patterns and artist splitting

**Files:** Create `src/title.rs` (unit tests inline in
`#[cfg(test)] mod tests`).

**Interfaces:**

- Produces:
  - `pub fn strip_noise(title: &str) -> String` — removes bracketed noise tags
    and trims.
  - `pub struct TitleGuess { pub artist: String, pub title: String, pub pattern: &'static str }`
  - `pub fn parse_title(title: &str) -> Option<TitleGuess>` — runs
    `strip_noise`, then patterns in order: `"artist-dash"`, `"bracket-quote"`,
    `"title-slash-artist"`.
  - `pub fn split_artists(s: &str) -> Vec<String>`.

Noise = a bracketed group (`【】`, `[]`, `()`) whose inner text,
case-insensitively, is one of / starts with: `mv`, `pv`, `official video`,
`official music video`, `official audio`, `official lyric video`, `lyric video`,
`lyrics`, `audio`, `music video`, `4k`, `hd`. Brackets with other content stay.

Patterns (each its own fn, `fn(&str) -> Option<(String, String)>` returning
`(artist, title)`):

- `artist-dash`: split on first `-` (also `–`, `—`); both sides non-empty.
- `bracket-quote`: `Artist「Title」…` or `Artist『Title』…`; text after the
  closing bracket is dropped (that is what the original regex did).
- `title-slash-artist`: split on **last** `/` (spaced), title left, artist
  right. A `artist-dash` title that itself is `「X」` gets its brackets trimmed
  (the original video: `かめりあ - 「アリバイ」 feat. 初音ミク`-style titles).

- [ ] **Step 1: Write failing tests:**
  - `strip_noise("アリバイ 【MV】")` == `"アリバイ"`;
    `strip_noise("Song (Official Video) [4K]")` == `"Song"`;
    `strip_noise("Song (Remix)")` == `"Song (Remix)"`.
  - `parse_title("Halozy - Lucky 7")` → artist `Halozy`, title `Lucky 7`,
    pattern `artist-dash`.
  - `parse_title("かめりあ「アリバイ」feat. 初音ミク")` → artist `かめりあ`,
    title `アリバイ`, pattern `bracket-quote`.
  - `parse_title("かめりあ - 「アリバイ」")` → title `アリバイ`.
  - `parse_title("ロキ / みきとP")` → artist `みきとP`, title `ロキ`, pattern
    `title-slash-artist`.
  - `parse_title("AC/DC Back In Black")` → `None` (unspaced slash).
  - `parse_title("just a title")` → `None`.
  - `split_artists("かめりあ feat. 初音ミク")` == `["かめりあ","初音ミク"]`;
    `split_artists("A ft B")` == `["A","B"]`;
    `split_artists("A Featuring B / C")` == `["A","B","C"]`;
    `split_artists("Simon & Garfunkel")` == `["Simon & Garfunkel"]`;
    `split_artists("A x B, C")` == `["A x B, C"]`.
- [ ] **Step 2:** `cargo test -p yt-audio title` → fails.

### Task 4: Metadata resolution

**Files:** Create `src/resolve.rs`, `tests/resolve.rs`.

**Interfaces:**

- Consumes: `info::Video`, `title::{parse_title, strip_noise, split_artists}`.
- Produces:
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum Source { Override, YouTube, Pattern(&'static str), Llm, Fallback }`
    with `Display` (`override`, `youtube`, `pattern:<name>`, `llm`, `fallback`).
  - `pub struct Field<T> { pub value: T, pub source: Source }`
  - `pub struct Tags { pub artists: Field<Vec<String>>, pub title: Field<String>, pub album: Field<String>, pub album_artist: String, pub date: Option<String> /* YYYY-MM-DD or YYYY */, pub comment: String /* webpage_url */, pub track_number: Option<u32> }`
  - `#[derive(Default)] pub struct Overrides { pub artists: Vec<String>, pub title: Option<String>, pub album: Option<String> }`
  - `pub struct Guess { pub artists: Vec<String>, pub title: Option<String>, pub album: Option<String> }`
  - `pub fn resolve(v: &Video, o: &Overrides, llm: Option<&dyn Fn(&Video) -> Option<Guess>>, llm_always: bool) -> Tags`

Per-field priority: Override → YouTube → (LLM if `llm_always`) → Pattern → (LLM
if not `llm_always` and title **or** artists still unresolved; call it at most
once) → Fallback. YouTube artists = `artists`, else `split_artists(artist)`.
Pattern artists = `split_artists(guess.artist)`. Fallback: title =
`strip_noise(v.title)`, artists =
`[channel or uploader, minus trailing " - Topic"]`. Every artist list goes
through `split_artists` per element and dedupe preserving order. `album` =
Override → YouTube album → LLM album → title value (source of title).
`album_artist` = first artist. `date` = `release_date` → `release_year` →
`upload_date`, formatted `YYYY-MM-DD`/`YYYY`.

  - `artist_dash_splits_feat`: artists `["かめりあ","初音ミク"]` source
    `Pattern("artist-dash")`, title `"アリバイ"`, album `"アリバイ"`,

### Task 7: Orchestration, dry-run and failure handling

**Files:** Modify `src/lib.rs`; extend `tests/cli.rs`; create `README.md`
(usage, cookie order, formats, metadata sources, LLM env vars — short, ls-posts
README style).

**Interfaces:**

- Consumes: everything above.
- Produces (in `lib.rs`): `fn process_entry(url, ctx) -> Result<Outcome, Error>`
  where `enum Outcome { Downloaded(PathBuf), Skipped(PathBuf), Planned }`
  (private; names are the implementer's to change).

Flow per CLI URL: cookies (`--no-cookies` → `None`; override → `Browser(s)`;
else `detect(home)`, warning
`yt-audio: no browser with a YouTube login found; continuing without cookies`
when `None`) → `listing_args` → folder base: playlist →
`output_dir.unwrap_or("./" + sanitize(playlist title))` with files flat inside;
single → `output_dir.unwrap_or(".")` joined with album folder. Per entry:
`info_args` → `resolve` → `destination` → if not `force` and a file `dest.*`
exists → `Skipped`; dry-run → print and `Planned`; else `download_args` + run →
path from stdout's last line → `write_tags`. Entry error →
`yt-audio: <url>: <error>` on stderr, continue. End: if any failed,
`yt-audio: N of M entries failed` and return 1.

Dry-run block (stdout), one per entry, blank line between:

```text
<dest>.<ext or *>
```
