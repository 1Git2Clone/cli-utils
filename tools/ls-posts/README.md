# ls-posts

Reconstruct post URLs from a gallery-dl download tree. The URL is inferred
from the folder topology and the filename, matching gallery-dl's default
naming conventions, so a tree of downloaded files can be turned back into a
list of links.

## Usage

```console
nix run .#ls-posts -- ./**/*    # URLs only
nix run .#ls-posts -- -l .      # path<TAB>url
ls-posts --format '{site}: {url}'
ls-posts --format '{json}'      # compact JSON per line
ls-posts --json .               # JSON array
ls-posts -0 .                   # NUL-separated
```

Each `PATH` may be a file or a directory; directories are walked recursively,
so `.` is as valid as a shell glob. Files with no recognised site or filename
are skipped with a summary on stderr (`-v` to see why, `-q` to silence it).

## Building

```console
nix build .#ls-posts   # from the repo root
cargo build            # from tools/ls-posts, inside `nix develop`
```

## Placeholders

`{path} {name} {ext} {site} {id} {username} {image} {page} {url} {post_url}`
`{media_url} {json}`

## Sites

Site folders may sit at any depth; the folder names below are relative.

| Folder | Filename | Post URL |
| --- | --- | --- |
| `twitter/<user>` | `<tweet_id>[_<n>]` | `https://x.com/<user>/status/<id>` |
| `facebook` | `<fbid>` | `https://www.facebook.com/photo/?fbid=<id>` |
| `pixiv` | `<id>_p<page>` | `https://www.pixiv.net/en/artworks/<id>` |
| `danbooru` | `<id>` | `https://danbooru.donmai.us/posts/<id>` |
| `safebooru` | `<id>` | `https://safebooru.org/index.php?page=post&s=view&id=<id>` |

Twitter: a bare tweet id is image 1; an explicit `_<n>` suffix is image `n`.
Facebook: every file is a distinct photo id, so one post can yield many URLs,
and a video extension maps to `/watch/?v=` rather than `/photo/?fbid=`.

## Development

Nix commands run from the repo root; cargo commands from this directory.

```console
nix develop                  # from the repo root
nix build .#ls-posts         # from the repo root
cargo test                   # from tools/ls-posts (inside `nix develop`)
cargo clippy -- -D warnings  # from tools/ls-posts
nix flake check              # from the repo root
pre-commit run --all-files   # from the repo root; what CI runs
```

Hooks are defined in `flake.nix`; `.pre-commit-config.yaml` is generated by
git-hooks.nix and is not tracked.
