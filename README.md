# cli-utils

A collection of small command-line utilities, one directory per tool. The
repository is language-agnostic: every tool is a Nix package, so whether it is
built by Cargo, Go, or a Python wrapper is an implementation detail.

## Tools

| Tool | Language | What it does |
| --- | --- | --- |
| [`ls-posts`](tools/ls-posts/) | Rust | Reconstruct gallery-dl post URLs from a folder tree |
| [`scripts`](tools/scripts/) | Bash, Python | Desktop and shell helpers, one package per script, named after its file |

## Install

The flake is meant to be consumed as an input by another flake, usually
`nixos-dotfiles`:

```nix
inputs.cli-utils.url = "path:/home/hutao/Projects/cli-utils";

home.packages = [ inputs.cli-utils.packages.${pkgs.system}.default ];
```

`packages.<system>.default` is a `symlinkJoin` of every tool, so one entry
installs all of them. Individual tools stay available as
`packages.<system>.<tool>`.

## Develop

```console
nix develop                 # cargo, rustc, clippy, rustfmt, rust-analyzer
nix build .#ls-posts        # one tool
nix build                   # every tool (the default bundle)
nix flake check             # evaluate packages, checks and shells
pre-commit run --all-files  # what CI runs
```

Hooks are defined in `flake.nix`; `.pre-commit-config.yaml` is generated by
git-hooks.nix and is not tracked. Cargo commands for a Rust tool run from that
tool's own directory, not the repo root.

## Layout

```text
flake.nix            # packages.<system>.<tool>, devShells, checks
tools/
  ls-posts/          # one directory per tool, with its own build files
  scripts/           # grouped by responsibility, one default.nix for all
```
